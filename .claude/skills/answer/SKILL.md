# 고객 답변 기록·반영

인자: $ARGUMENTS

당신은 **오케스트레이터**다. `CLAUDE.md` §5·§7·§8과 `.claude/reference/git-ops.md`를 따른다. 답변 기록은 오케스트레이터 예외 작업이지만, **산출물 반영은 담당 팀 에이전트에게 위임한다.**

---

## 1. 대상 질문 찾기
- 프로젝트는 `CLAUDE.md` §10 규칙으로 정한다. 이하 `{PROJECT}` = `projects/<SLUG>`.
- `{PROJECT}/pm/requests/QNA.md`에서 대상 질문을 찾는다: Q ID가 주어지면 그 질문, 없으면 답변 내용과 `open` 질문을 대조한다. 여러 질문에 걸친 답변이면 질문마다 나눠 기록한다.
- 어느 질문에도 해당하지 않는 정보(새 요구·변경 요청·자료 제공)이면 새 Q로 억지로 만들지 말고 PM에게 확인한다 → 기능·시안 제안은 `/suggest`, 승인된 내용의 변경은 `/change-request`.
- 대응이 애매하면 AskUserQuestion으로 어느 질문의 답인지 확인한다.

## 2. 기록
- 해당 행의 "답변 (원문)"에 PM이 전달한 내용을 **수정 없이** 적고, 답변일·출처(고객 이름/PM), 상태 `answered`를 기록한다.
- 답변에 파일이 있으면 `/suggest`의 첨부 규칙대로 `pm/requests/attachments/Q-xxx/`에 보관한다.
- STATUS.md "TBD·콘텐츠 수급"의 미답변 질문 수를 갱신하고, ACTIVITY에 `* 결정: Q-xxx 고객 답변 — {요약} (PM)`을 추가해 커밋한다 (`chore: Q-xxx 고객 답변 기록`).

## 3. 반영
1. 산출물에서 `[TBD: Q-xxx]`를 Grep으로 찾아 영향 문서를 정한다(계획서 §2.4·§7·§8, 요구사항, 화면정의서, 디자인, 기술 설계 등).
2. 영향 문서의 상태에 따라 처리한다.

| 영향 문서 상태 | 처리 |
|---|---|
| 아직 승인 전 (`draft`·`in-review`·`revision`) | 문서 Owner를 호출해 답변 반영 지시(QNA 경로, Q ID) → 버전 증가, 변경 이력에 Q ID → 커밋 |
| 승인됨 (`approved`) — 답변이 내용을 **바꾸지 않고** `[TBD]`만 채움 | Owner를 호출해 `[TBD]` 해소만 반영(버전 x.y+1, 변경 이력에 Q ID) → 커밋. 다음 게이트 보고에 "답변 반영" 목록으로 알린다 |
| 승인됨 — 답변 때문에 범위·기능·디자인·스택이 **바뀜** | 반영하지 않고 `.claude/skills/change-request/SKILL.md` 절차로 CR 생성(요청 원문에 Q ID·답변 인용) |
| 스택 프리셋·진행 모드·디자인 프로필 판단에 영향 | PM에게 보고하고 결정을 받는다(G2 전이면 프리셋 잠정값 갱신, 후면 CR) |

3. 반영이 끝나면 QNA 행의 "반영 위치"를 채우고 상태를 `applied`로 바꿔 커밋한다(ACTIVITY `수정` 항목).

## 4. PM 보고
```

- 남은 미답변 질문: n건 (기한 지난 것: Q-…)
```
