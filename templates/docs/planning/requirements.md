## 8. 제출 전 자기 점검 (planner — 교차 검토 전)
- [ ] 요청 추적표(§1.1)에 빈 칸이 없다 (모든 요청 항목이 REQ 또는 미반영 사유를 가진다)
- [ ] 제안 기능(§3.1)에 PM 결정이 모두 기록되었고, 승인 항목만 REQ-F로 옮겼다
- [ ] 모든 REQ에 측정 가능한 수용 기준이 있다 (qa가 그대로 테스트할 수 있다)
- [ ] 모든 SCR이 REQ와 연결되고, 모든 Must REQ가 SCR 또는 비기능 항목에서 다뤄진다
- [ ] 모든 `[TBD`에 Q ID가 붙어 있고 QNA에 등록되어 있다
- [ ] 폼(§3.3)·콘텐츠 유형(§5.2)·동적 기능 목록(§3.2)이 해당 시 작성되었다
- [ ] 법적 고지(§5.1)·마감 품질(`polish-checklist.md`)을 점검했다
- [ ] 리뉴얼이면 IA의 리다이렉트 맵·콘텐츠 이관 목록을 작성했다
- [ ] 페이지·기능 수를 계획서 §2.5 규모 초안과 비교해 변화와 사유를 적었다
